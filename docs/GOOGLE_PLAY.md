## 4. Графика

Для Android снят отдельный набор: iPhone-изображения 1320 × 2868 имеют
отношение сторон больше 2:1 и не проходят требования Google Play. Порядок
пяти готовых кадров: каталог, блюдо, корзина и баллы, оформление, профиль.
Все PNG — 1080 × 1920, RGB без alpha. Экран живого заказа не снимали,
поскольку для него пришлось бы создать заказ на production и затронуть
реальные планшеты Poster.

## 7. Data safety

Ответы должны описывать не только Flutter-клиент, но и backend PizzBurg.
Реклама и передача данных сторонним рекламным сетям отсутствуют.

| Категория Google | Данные | Собираются | Передаются третьим лицам | Назначение |
|---|---|---|---|---|
| Personal info | имя, номер телефона | да | нет | управление аккаунтом, заказ, связь |
| Location | адрес доставки (approximate location) | да | нет | доставка и работа приложения |
| Financial info | история покупок | да | нет | заказ, история, программа лояльности |
| App activity | поиск в приложении, просмотры товаров, действия с корзиной | да | нет | аналитика и улучшение приложения |
| Device or other IDs | push-токен и случайный ID установки | да | Firebase Cloud Messaging как service provider | push и аналитика |

Дополнительные ответы:

- Data is encrypted in transit: **Yes** — production работает по HTTPS.
- Users can request that data is deleted: **Yes** — в приложении есть
  «Профиль → Настройки приложения → Удалить аккаунт».
- Data collection is required for account/order data; просмотр каталога без
  входа доступен, поэтому часть аналитики собирается и без аккаунта.
- Ephemeral processing: **No** для перечисленных данных.

Перед отправкой анкеты ещё раз сверить формулировки с production-сборкой и
актуальным SDK Firebase. Firebase используется как обработчик для доставки
push, а не для рекламы.

## 9. Тестирование и выпуск

1. Загрузить подписанный `.aab` во **внутреннее тестирование**.
2. Проверить установку по ссылке, вход, оформление, push и удаление аккаунта.
3. Если аккаунт Play Console личный и создан после 13 ноября 2023 года,
   провести закрытый тест: минимум 12 участников должны быть включены
   непрерывно 14 дней.
4. После прохождения требований запросить доступ к production и отправить
   релиз на проверку.

Готовый подписанный bundle сохранён в
`export/stores/pizzburg-1.0.0+1-release.aab`. Он собран с боевым
`API_URL=https://api.pizzburg.kz`; промежуточная папка `mobile/build/`
очищена после сборки.

## 10. Перед публикацией

- Развернуть backend со страницей поддержки и проверить оба публичных URL.
- Загрузить пять готовых Android-скриншотов из папки Ready.
- Проверить короткие описания на лимит 80 символов в Play Console.
- Загрузить icon и feature graphic в нужных форматах.
- Указать тестовый номер и код в App access.
- Заполнить Data safety по таблице выше и сохранить экспорт ответов.
- Загрузить подписанный AAB сначала во внутренний трек.
