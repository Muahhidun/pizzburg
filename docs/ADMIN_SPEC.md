# ТЗ: веб-админка PizzBurg Delivery (фронтенд)

Задание для ИИ-агента/разработчика. Перед началом прочитать
`docs/HANDOFF.md` и `docs/PROJECT.md` — там весь контекст проекта.

## Цель

Заменить CLI-скрипты (`backend/prisma/storefront.ts`) веб-интерфейсом
владельца заведения. Референс по духу — админка FoodPicasso
(app.foodpicasso.com: светлая, карточная, простая), но делаем чище и
быстрее. Язык интерфейса — русский. Пользователь — владелец, не айтишник;
часто заходит с телефона → мобильная адаптивность обязательна.

## Стек

- Next.js (App Router) + TypeScript, папка `admin/` в монорепозитории.
- Tailwind + shadcn/ui (или аналог без тяжёлых зависимостей).
- Данные — REST бэкенда NestJS (`http://localhost:3210`, в проде URL
  Railway; базовый URL в env `NEXT_PUBLIC_API_URL`).
- Drag-and-drop: dnd-kit.
- Никакого SSR-усложнения: клиентские компоненты + fetch хватает.

## Авторизация

V1: статический админ-токен в env (`ADMIN_TOKEN`), передаётся заголовком
`X-Admin-Token`; на бэке — простой guard (добавить). Логин-форма с одним
полем «токен». Полноценные роли — позже.

## Экраны

### 1. Витрина (главный экран)

Две колонки (на мобиле — стек):
- **Категории** (AppCategory): список в порядке sortOrder.
  Перетаскивание порядка (dnd), toggle видимости, переименование
  инлайн, счётчик активных товаров. Бейдж «пустая», если 0.
- **Товары выбранной категории**: карточка = фото-миниатюра, имя витрины
  (displayName ?? name), цена (priceOverride ?? price), бейджи: отдел
  («Основной»/«Sunday»), «стоп-лист» (isActive=false — только индикатор,
  управляется кассой), toggle isVisible. Редактирование: displayName,
  displayDescription, priceOverride (пусто = кассовая цена), перенос в
  другую категорию (select), sortOverride перетаскиванием.

Кнопка «Синхронизировать с Poster» (POST /poster/sync/:tenantId) с
индикатором результата по отделам.

### 2. Заказы

Лента за сегодня/дату (фильтр). Строка: №, время, тип
(доставка/самовывоз), клиент (имя, телефон), сумма, метод оплаты,
агрегированный статус + статусы частей по отделам (чипы «Основной:
принят», «Sunday: новый»). Клик — детали: состав (с подарками —
помечать «акция»), адрес, комментарий, история. Автообновление раз в
15 сек. Кнопка «Обновить статусы» (POST /orders/by-id/:id/sync-status).

### 3. Акции

Список Promotion: имя, условие («2 из Пиццы»), подарок, промокод или
«автоматически», toggle isActive. Форма создания/редактирования:
категория условия (select из AppCategory), количество, подарочный товар
(поиск по товарам), giftQty, repeatPerCart, промокод (опционально),
период действия (опционально).

### 4. Настройки

- Доставка: minOrder, fee, freeFrom (Tenant.settings.delivery).
- Аккаунты Poster: список (имя, порядок, активность), добавление
  (имя + токен) — токен вводится, но никогда не показывается обратно.
- Время работы точки (Venue.workingHours) — таблица день/часы.

## API-контракт

Существует: `GET /menu/:slug`, `POST /poster/sync/:tenantId`,
`POST /cart/:slug/preview`, `POST /orders/:slug`,
`GET /orders/by-id/:id`, `POST /orders/by-id/:id/sync-status`.

Нужно ДОБАВИТЬ на бэке (в том же стиле, под guard админ-токена),
фронт проектировать под этот контракт:

```
GET    /admin/storefront                 — категории + товары (всё, вкл. скрытые)
PATCH  /admin/categories/:id             — {name?, sortOrder?, isVisible?}
PATCH  /admin/products/:id               — {displayName?, displayDescription?,
                                            priceOverride?, appCategoryId?,
                                            sortOverride?, isVisible?}
GET    /admin/orders?date=&status=       — лента заказов с частями
GET    /admin/promotions                 — список
POST   /admin/promotions                 — создание
PATCH  /admin/promotions/:id             — правка/toggle
GET    /admin/settings                   — settings + venues + posterAccounts (без токенов)
PATCH  /admin/settings                   — delivery и пр.
POST   /admin/poster-accounts            — {name, token, sortOrder}
```

## Правила

- Все правки витрины действуют мгновенно (optimistic UI + revalidate).
- Цены в ₸ целыми, форматировать `2 550 ₸`.
- Ничего не удаляем физически — только скрытие/деактивация.
- Пустые категории автоматически не показываются в приложении — в
  админке это просто бейдж, не ошибка.
- Не трогать данные, приходящие из Poster (name, price, стоп-лист) —
  они перезаписываются синком; редактируются только витринные поля
  (displayName, priceOverride и т.д.).

## Definition of done (v1)

Владелец без CLI может: отсортировать/переименовать/скрыть категории и
товары, поменять цену витрины, увидеть ленту заказов со статусами частей,
создать акцию «2+1», поменять настройки доставки, запустить синк.
Всё работает с телефона.
