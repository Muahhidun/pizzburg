# Резервные копии базы

База — Postgres 18 в Railway, около 24 МБ, дамп сжимается до ~1 МБ.
В ней 14 975 клиентов, история заказов, баллы и юридические документы.
Второго экземпляра этих данных нет нигде.

## Три уровня, и нужны все три

| Уровень | От чего спасает | Кто делает |
|---|---|---|
| Бэкапы Railway | случайное удаление таблицы, сбой диска | владелец, включается в панели |
| Копия на своей машине | потеря доступа к Railway, закрытие аккаунта | `scripts/backup-db.py` |
| Проверка восстановления | копия, которая на самом деле не разворачивается | вручную, раз в месяц |

Первые два без третьего — это надежда, а не резервирование.

## Уровень 1. Бэкапы Railway

Railway → проект → сервис **Postgres** → вкладка **Backups**. Включить
ежедневные, срок хранения по максимуму на вашем тарифе.

Это первая линия и самая удобная: восстановление делается в пару кликов
в той же панели. Но она не спасает, если пропадёт доступ к аккаунту
Railway — поэтому есть второй уровень.

## Уровень 2. Копия у себя

```bash
python3 scripts/backup-db.py
```

Кладёт файл в `~/PizzBurg-backups/pizzburg-ГГГГММДД-ЧЧММ.dump`, права 600,
хранит 14 последних копий (`--keep N` меняет).

Дамп снимается **внутри контейнера** Railway: сервер там Postgres 18, а
локальные утилиты обычно старее и с таким сервером работать отказываются.
Публичного адреса у базы нет, и заводить его не надо — `railway ssh` уже
даёт доступ.

**Каталог с копиями — не репозиторий и не облако без пароля.** В дампе
персональные данные всех клиентов: телефоны, имена, адреса доставки.
Хранить как пароли от банка.

Раз в неделю имеет смысл унести свежую копию на внешний диск или в
зашифрованное хранилище: ноутбук — такая же единственная точка отказа,
как и Railway.

## Уровень 3. Проверка восстановления

Раз в месяц и обязательно после любых изменений в схеме.

```bash
export PATH="/opt/homebrew/opt/postgresql@18/bin:$PATH" LC_ALL=C
pg_ctl -D /opt/homebrew/var/postgresql@18 -l /tmp/pg18.log -o "-p 5433" start
createdb -p 5433 restore_check
pg_restore -p 5433 -d restore_check --no-owner --no-privileges \
  ~/PizzBurg-backups/<свежая копия>.dump
```

Сверить числа с боевыми:

```bash
psql -p 5433 -d restore_check -tAF'|' -c 'select
  (select count(*) from public."Customer"),
  (select count(*) from public."Order"),
  (select count(*) from public."Product"),
  (select count(*) from public."LoyaltyTransaction")'
```

Убрать за собой:

```bash
dropdb -p 5433 restore_check
pg_ctl -D /opt/homebrew/var/postgresql@18 stop
```

`LC_ALL=C` обязателен: без него Postgres 18 на macOS падает при старте с
«postmaster became multithreaded during startup».

## Восстановление на боевом

Если база в Railway потеряна:

1. Создать в проекте новый сервис Postgres.
2. Прописать его `DATABASE_URL` сервису backend.
3. Развернуть последнюю копию — так же, как в проверке выше, но в новую
   боевую базу.
4. Прогнать `npx prisma migrate deploy`, если копия старше последней
   миграции.
5. Проверить: открывается меню, виден список заказов в админке, у клиента
   на месте баллы.
