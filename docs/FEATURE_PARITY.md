# Паритет PizzBurg со SmartPicasso

Документ собирает в одном месте все функции из аудита 71 скриншота
SmartPicasso/FoodPicasso и фактическое состояние нашего кода на 07.08.2026.

Легенда: **✅ готово** · **🟡 частично** · **⬜ нет** · **🚫 не берём**.

## Принцип лояльности

- Единственный источник кешбэка для клиента — **наше приложение и наш
  `LoyaltyTransaction` ledger**.
- Бонусы Poster, включая его автоначисление 7%, не импортируем, не
  показываем, не сверяем и не считаем за баланс приложения.
- Начисление и списание баллов делает наш backend. При списании позиции
  уходят в Poster полными ценами, а баллы закрываются методом
  «Личная интеграция», чтобы сходилась смена.
- Импортировать нужно балансы **кэшбэка старого приложения**, если они есть
  в выгрузке. Балансы Poster к этой миграции не относятся.

| Начисление кэшбэка | Берём, P1 | ✅ | После `DELIVERED`, идемпотентно. Новое правило: при оплате баллами или применении акции по умолчанию начисление 0; три политики настраиваются независимо. Нужен повторный staging-тест новых правил. |

| Совместимость баллов и акций | Берём, P1 | ✅ | По умолчанию взаимоисключающие. Flutter предлагает явный выбор «акция или баллы», backend не позволяет обойти правило; администратор может разрешить совмещение. |
| Журнал транзакций с заказом | Берём, P1 | ✅ | EARN/SPEND/ADJUST видны клиенту и администратору. |

## Очерёдность переноса

1. **Инфраструктура:** R2 + Railway staging, заполнение фото и прогон всего
   сквозного сценария в dry-run.
2. **До публичного запуска:** кэшбэк приложения, FCM-статусы, только
   самовывоз, расписание/предзаказ, методы оплаты/сдача, причины отмены,
   оферта/privacy, баннеры акций и базовые типы скидок.
3. **Первые месяцы:** сегменты и массовые пуши, отзывы, расширенные акции,
   аналитика за период, CSV, ручной апселл.
4. **Позже:** курьерский модуль и его аналитика, рефералка, smart-рекомендации,
   приоритетная доставка, чаевые и SaaS-функции.

Исходный поэкранный аудит и обоснования приоритетов: `docs/SMARTPICASSO_AUDIT.md`.
