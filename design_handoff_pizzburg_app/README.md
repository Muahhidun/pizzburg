# Handoff: PizzBurg — мобильное приложение доставки (направление «Сигнал», фирменная палитра)

## Overview

Приложение доставки еды одного заведения (PizzBurg, Экибастуз, Казахстан): пиццы, бургеры,
донеры, хот-доги, крылья, комбо, напитки. Заведение уходит с арендованной платформы на своё
приложение; клиентская база ~15 000 человек, ключевой сценарий — **повторный заказ**.

В этом пакете — утверждённое визуальное направление и кликабельный прототип шести основных
экранов плюс всех обязательных состояний. Задача разработчика: воспроизвести эти экраны
в целевом приложении (**Flutter**, один код на iOS / Android / веб), а не переносить HTML.

## About the Design Files

Файлы в пакете — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие
внешний вид и поведение, а не production-код для копирования. HTML/CSS здесь нужны только
как точный источник значений: цветов, размеров, отступов, радиусов, копирайта и логики
состояний.

Реализовывать нужно **на Flutter**, средствами и паттернами целевого проекта
(`ThemeData` / `ColorScheme` / `TextTheme`, свои виджеты, свой роутер и state-management).
Если в проекте уже есть дизайн-система — использовать её примитивы, подставив токены ниже.

Открывать прототип: `PizzBurg Прототип.dc.html` в браузере (кликабельный, все переходы
работают). `PizzBurg Направления.dc.html` — сравнение пяти визуальных направлений,
из которых выбрано направление **1c «Сигнал»**; остальные оставлены как контекст решения.

## Fidelity

**High-fidelity (hifi).** Цвета, типографика, отступы, радиусы и копирайт — финальные.
Воспроизводить пиксель-в-пиксель по значениям из раздела Design Tokens. Размер макета —
390 × 844 логических пикселя (iPhone 13/14 base), верстать адаптивно от него: один
адаптивный layout на телефон / планшет / веб, отдельных макетов нет.

## Design Tokens

### Цвета

| Токен | Значение | Где используется |
| --- | --- | --- |
| `ink` | `#0E0D10` | основной текст, чёрные поверхности (хедер каталога, экран статуса, тёмный блок баллов в корзине), выбранные сегменты |
| `accent` | `#F7941D` | все действия: кнопки «В корзину», «Оформить», «Заказать», «+» в списке, активные чипсы категорий и добавок, выбранный адрес, ссылки-действия |
| `benefit` | `#E6007E` | только выгода: сумма списанных баллов, «0 ₸» у подарка, бейдж «Подарок», карточка баллов в профиле, галочки этапов статуса, ползунок баллов |
| `surface` | `#FFFFFF` | фон экранов, карточки |
| `muted` | `#8B8792` | подписи, вес/состав, неактивные табы |
| `line` | `rgba(14,13,16,.08)` | разделители строк списка, граница таб-бара |
| `border` | `rgba(14,13,16,.12)` | контур неактивных пилюль и полей |
| `fillSoft` | `rgba(14,13,16,.05)` | фон неактивных чипсов, счётчиков количества, второстепенных кнопок |
| `accentSoft` | `rgba(247,148,29,.10)` | подложка выбранного адреса, круг в пустой корзине и на ошибке сети, подсказка про кэшбэк |
| `benefitSoft` | `rgba(247,148,29,.14)` → на тёмном | бейдж подарка: фон `rgba(247,148,29,.14)`, текст `benefit` |
| `warnSoft` | `rgba(247,148,29,.10)` | подсказка «добавьте ещё на N ₸ — палочки в подарок», текст `#A96410` |

Правило палитры: **чёрный — основа (как круг в логотипе), оранжевый — действия,
маджента — выгода.** Больше цветов не вводить. Тёмная тема пока не нужна.

Мультитенантность: `accent` и `benefit` обязаны быть параметрами темы (в прототипе это
CSS-переменные `--acc` / `--ben` и props `acc` / `ben`). Ни один экран не завязан на логотип;
логотип в прототипе направления 1c не используется вообще.

### Отступы и сетка

- Базовая сетка **4**.
- Горизонтальные поля экрана — **22**.
- Между смысловыми блоками — **22–24**; внутри блока — **8–12**.

- Нижняя safe-area: таб-бар `padding: 10px 0 18px`.
- Статус-бар: высота 44, padding по бокам 24.

## Screens / Views

### 1. Каталог (главный)

**Назначение.** Человек либо повторяет прошлый заказ одним тапом, либо выбирает позиции.

**Layout сверху вниз:**

1. **Тёмный хедер** (`ink`, radius 0 0 30 30, padding 10/22/26):
   - Слева двухстрочно: «Доставим на» (12/1.35, 500, opacity .7) и «Сатпаева, 38А ▾»
     (13.5, 600) — тап открывает выбор адреса.
   - Справа пилюля со временем: фон `rgba(255,255,255,.14)`, текст 12/600 — «35 мин»
     для доставки, «готово к 21:30» для самовывоза, «самовывоз» когда доставка закрыта.
   - Заголовок «Тот же заказ?» — Unbounded 27/1.1, 700, −.03em, margin-top 20.
   - **Блок повтора**: белая капсула radius 24, padding 12/14, внутри миниатюра 44×44
     (radius 15), состав прошлого заказа (11.5/1.35, 500), сумма Unbounded 13.5/700,
     справа кнопка «Повторить» — `accent`, белый текст, 12/600, padding 11/15, капсула.
     Блок скрывается, когда заведение закрыто; управляется флагом `repeatBlock`.

2. **Переключатель «Доставка / Самовывоз»**: две равные капсулы, padding 12/0, gap 7,
   активная — `ink` + белый текст 600; неактивная — белый фон, текст `muted`,
   контур `border`. Когда заведение закрыто, «Доставка» задизейблена
   (фон `rgba(14,13,16,.04)`, текст `rgba(139,135,146,.6)`, тап игнорируется).

3. **Категории** — горизонтальный скролл чипсов, gap 8, padding 10/15, капсула;
   активный — `accent` + белый 600; неактивный — `fillSoft` + `muted` 500.
   В прототипе: Пиццы / Бургеры / Закуски. В проде — полный список категорий бэкенда.

4. **Список товаров** — вертикальный скролл, строка:
   миниатюра 76×76 radius 22 → название (14.5/1.2, 600) + состав и вес (11/1.45, `muted`)
   → справа цена (Unbounded 14/700, без «₸» в списке: `3 400`) и под ней круглая кнопка
   «+» (`accent`, белый, padding 8/14, капсула). Разделитель `line`.
   **Стоп-лист**: строка `opacity .45`, фото `grayscale(1)`, вместо состава — «Закончилась,
   вернём завтра», вместо «+» — статичная пилюля «нет» (`fillSoft`, `muted`); тап по строке
   открывает карточку товара в состоянии «закончилась».

5. **Плавающая кнопка корзины** (появляется, когда корзина не пуста): капсула `accent`,
   слева итог Unbounded 16/700, справа белая пилюля «Корзина · N».

6. **Таб-бар** — 4 равные вкладки: Меню / Корзина / Заказы / Профиль. Иконки минимальные
   (2×2 квадрата 6px, корзина, три линии, круг), 15×15, активная вкладка — `accent`,
   неактивная — `muted`; подпись 10.5/500 (активная 600). **Счётчиков суммы и баллов в
   табах быть не должно** — это прямая ошибка старого приложения.

### 2. Карточка товара

- Верхняя строка: круглая кнопка «←» 36×36 (`fillSoft`), справа пилюля с весом
  (`fillSoft`, `muted`, 11.5/500).
- Фото на всю ширину, высота 200, radius 26, `object-fit: cover`.
- Название — Unbounded 24/1.15, 700, −.03em.
- Состав — 12.5/1.55, `muted`.
- **Размер** (только для пиццы): три равные капсулы 25 / 30 / 35 см, активная `ink` + белый;
  дельты к цене: −400 / 0 / +600 ₸.
- **Добавки** — чипсы с подписью «Название +цена», wrap, gap 7; выбранная — `accent` + белый,
  невыбранная — белый фон + контур `border`.
  Пицца: Двойная моцарелла +450, Пепперони +600, Бортик с сыром +700, Соус чесночный +200.
  Бургеры: Бекон +500, Двойной чеддер +400, Халапеньо +300, Соус +200.
  Закуски: Соус сырный +200, Соус барбекю +200.
- **Нижняя панель**: капсула `ink`, слева итоговая цена позиции с добавками
  (Unbounded 18/700), справа кнопка «В корзину» (`accent`, белый, 13/600, padding 15/22).
- **Состояние «закончилась»**: фото `grayscale(1) opacity .45`, вместо конфигуратора — блок
  `rgba(14,13,16,.04)` radius 26 с заголовком «Сегодня закончилась» (Unbounded 16/700) и
  текстом «Вернём в меню, когда привезут продукты. Можем написать, как только появится.»,
  кнопка «Сообщить о поступлении» (`ink`). Ниже — «Похожее в наличии»: две карточки
  radius 22, фото 72, название 12/600, цена Unbounded 12.5/700. Нижней панели нет.

### 3. Корзина

- Заголовок «Корзина» — Unbounded 24/1.1, 700.
- Строка позиции: миниатюра 58×58 radius 20 → название 13/1.25 600, под ним конфигурация
  («30 см · + Бекон») 10.5/1.3 `muted`, цена строки Unbounded 13/700 →
  счётчик «− N +» (`fillSoft`, капсула, padding 6/10, gap 8). Удаление — уменьшением до 0.
- **Подарок** (позиция с ценой 0 ₸): появляется автоматически при сумме товаров ≥ 5 000 ₸ —
  «Сырные палочки», цена «0 ₸» цветом `benefit`, бейдж «Подарок за 5 000 ₸»
  (`rgba(247,148,29,.14)`, текст `benefit`, 10/600).
  Если сумма меньше — подсказка `warnSoft`: «Добавьте ещё на N ₸ — сырные палочки в подарок».
- **Промокод**: капсула `fillSoft`, слева поле ввода (placeholder «Промокод», 12.5/500),
  справа кнопка «Применить» (`ink`, белый, 12/600). Успех — строка `benefit`: «Промокод PB10
  применён — минус 10% на блюда». Ошибка — строка `accent`: «Такого промокода нет. Рабочий
  пример: PB10». (В проде проверка на бэкенде; PB10 — демо-код прототипа, −10% на товары.)
- **Списание баллов** — тёмный блок `ink` radius 28, padding 20:
  - строка «Списать баллы» (12.5/600) + «1 006 доступно» (11/500, opacity .6);
  - сумма списания — Unbounded 28/700 цветом `benefit`;
  - ползунок: min 0, max = доступные баллы, ограниченные суммой заказа после промокода,
    step 50; трек `rgba(255,255,255,.2)` высотой 4, бегунок 22×22 круг `benefit`;
  - подписи концов «0» и максимум (10.5/500, opacity .55);
  - две кнопки «Не списывать» / «Максимум» (`rgba(255,255,255,.12)`, 11.5/600).
  - **Дробных баллов в интерфейсе быть не должно** — только целые, формат «1 006».
- **Итог**: строки «Товары · N», «Доставка» (бесплатно / самовывоз), «Промокод PB10»
  (цвет `benefit`), «Баллы» (цвет `accent`, «−600 ₸») — 12/1.7, 500, `muted`;
  затем капсула `accent`: слева итог Unbounded 18/700, справа белая пилюля «Оформить».
- **Пустая корзина**: круг 92 `accentSoft` с контуром корзины внутри, заголовок «Пока пусто»
  (Unbounded 19/700), текст «Можно повторить прошлый заказ — это быстрее всего», карточка
  прошлого заказа (контур `border`, radius 26), кнопка «Повторить заказ» (`accent`) и
  «Открыть меню» (`fillSoft`).

## Interactions & Behavior

- Переключение **доставка / самовывоз** меняет ETA, подпись адреса на оформлении
  («Куда привезти» / «Откуда забрать») и строку «Доставка» в итоге.
- Категория — фильтр списка (в проде лучше как якоря непрерывного скролла).
- «+» в списке добавляет товар в базовой конфигурации (для пиццы — 30 см, без добавок).
- Тап по строке открывает карточку; из карточки «В корзину» добавляет сконфигурированную
  позицию и **сразу открывает корзину**.
- Одинаковые конфигурации схлопываются в одну строку с количеством; разные конфигурации
  одного товара — отдельные строки (ключ строки = id товара + конфигурация).
- Изменение состава корзины **сбрасывает списание баллов в 0** (иначе списание может
  превысить сумму). Ползунок всегда ограничен `min(баланс, сумма − скидка по промокоду)`.
- «Заказать» создаёт заказ и открывает статус; этапы в прототипе продвигаются каждые 4 с
  (демо) — в проде по данным бэкенда (polling или push).
- Отмена: подтверждение с причиной → заказ снят, корзина очищена, экран «Заказы».
- Переходы: без сложной анимации, стандартные push/pop платформы; hover-состояний нет
  (мобильный приоритет), для веба добавить лёгкое затемнение фона кнопки на hover.
- Чего **не делать**: баннерных карусел на первом экране, счётчиков в табах, кнопки
  «списать все баллы» без выбора суммы, дробных баллов, плотной сетки карточек без воздуха.

## State Management

Состояние прототипа (минимально необходимый набор):

| Переменная | Тип | Смысл |
| --- | --- | --- |
| `tab` | menu / cart / checkout / orders / profile | активная вкладка / стек |
| `screen` | catalog / product / cart / status / orders / profile | экран внутри вкладки |
| `cat` | string | выбранная категория |
| `mode` | delivery / pickup | способ получения |
| `product` | товар \| null | открытая карточка |
| `size` | 0..2 | выбранный размер пиццы |
| `addons` | map index→bool | выбранные добавки |
| `cart` | список строк `{key, id, name, img, sub, price, qty}` | корзина |
| `promo`, `promoOk`, `promoBad` | string, bool, bool | промокод и результат проверки |
| `points` | int | сумма списания баллов |
| `addr` | int | выбранный сохранённый адрес |
| `pay` | cash / card / online | способ оплаты |
| `change` | int | сдача с суммы (только для наличных) |
| `slot` | asap / «22:00» / … | время доставки |
| `comment` | string | комментарий курьеру |
| `active`, `stage` | bool, 0..4 | есть активный заказ и его этап |
| `cancelOpen`, `reason` | bool, int | шит отмены и выбранная причина |

Вычисляемые значения: `subtotal`, `promoCut = 10% от subtotal`, `maxPoints`,
`total = subtotal − promoCut − points`, `giftEarned = subtotal ≥ 5000`.

Данные с бэкенда: категории и товары со стоп-листами, сохранённые адреса, слоты предзаказа,
баланс и история баллов, история заказов, статус активного заказа, правила акций и подарков,
уровни кэшбэка.

Формат денег: тенге, **целые числа, разряды тонким пробелом** — «5 050 ₸». В строке списка
цена без символа («3 400»), в итогах и кнопках — с «₸».

Иконки в прототипе нарисованы простыми примитивами (квадраты, линии, круги) — это
плейсхолдеры. В проде взять иконки из библиотеки проекта, сохранив вес линии ~1.7 px
и размер 15×15 в таб-баре.

Фотографии в каталоге обрезаются `cover`; отдельного кропа под квадрат не делали — при
интеграции проверить, что центр блюда не режется на квадратных миниатюрах.
